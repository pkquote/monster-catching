# Creature Passives Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every creature has a rolled passive, can unlock an Affinity passive, and has exactly one of the two active. Passives work in battle (always-on, triggered, protection, game-specific) and on the overworld (lead creature).

**Architecture:**
- **Core data:** passives are a JSON content category (`PassiveDef`).
- **Creatures:** each creature stores `passive`, `affinity_passive` and `active_passive`.
- **Battle rules:** a new battle part, `PassiveRules`, supplies always-on effects to the existing `engine.passives(b)` pipeline and runs triggers from hooks in `BattleEngine`, `FieldRules` and `ActionRunner`.
- **Shared helper:** a pure `core/progress/passives.gd` handles rolling, growth carry-over, unlocking and overworld multipliers.

**Tech Stack:** Godot 4.7.2 .NET, typed GDScript, gdUnit4 6.2.3.

**Spec:** [documentation/specs/2026-11-04-passives-design.md](../specs/2026-11-04-passives-design.md)

## Global Constraints

- **Layers:** `core/` stays pure (no nodes or autoloads), and screens live in `game/`.
- **Data rules:** every new op is registered in `DataSchemas.EFFECT_OPS`, `EffectOps` and `tools/generate_compendium.gd`. New content lives in `data/passives/*.json`.
- **Creature fields:**
  - `active_passive` is `"rolled"` or `"affinity"`, default `"rolled"`.
  - An empty `passive` or `affinity_passive` means none.
  - Only the active passive has any effect.
- **Unlocking:** an Affinity passive unlocks when a track first reaches `balance.growth_affinity_threshold` (30). Each creature unlocks at most one.
- **Stacking:** multipliers multiply, and the same aura id from two allies counts once. Effects run by a trigger never fire passive triggers (a depth guard).
- **Rolling:** `CreatureInstance.create` with no RNG takes the species' first listed passive (deterministic, which keeps tests stable). Game creation sites pass an RNG and roll uniformly.
- **Saves:** `SaveGame.SCHEMA` = 4.
- **Tests:** test first. Use the `WorldTest` helper for overworld suites. Test output must stay clean.
- **Commits:** none. The user authors every commit.

## Review Focus

1. **Existing tests' numbers changing:** real species now carry passives. A test that checks unrelated maths must not shift because Tidepup now has Tidal Heart. Tests that need neutral maths set `passive = ""`. Task 2 pins `create()`'s deterministic default, and each engine task re-runs the full suite.
2. **Benched or fainted creatures:** auras and always-on effects apply only from creatures on the field and standing. Triggers never fire for a fainted creature, or after the battle is over (Tasks 4 and 5).
3. **Saves:** migrating a save with creatures in storage and an unknown species fills the storage creatures, logs and skips the unknown species, and doesn't crash (Task 2).
4. **Immunity versus absorb:** `absorb_type` on a type the creature is immune to (type multiplier 0) still heals and doesn't count as a hit. `energy_discount` never makes a cost negative (Tasks 5 and 6).
5. **A passive unlocked without a level-up:** a creature whose track crosses 30 in a battle where it didn't level still gets a progress entry and the Passive Unlocked screen (Task 3).

### Task 3: Unlocking, growth carry-over and progress entries

**Files:**
- Modify:
  - `core/progress/passives.gd`: `try_unlock`, `carry_over`.
  - `core/progress/progression.gd`: `award_affinity` calls `try_unlock`, and `apply_growth` calls `carry_over`.
  - `core/progress/progress_entry.gd`: the new field.
  - `progress_entry(db, c, level_before, passive_before := "")`.
  - `game/battle/battle_launcher.gd`: `apply_results` records `affinity_passive` before the commit.
- Test: `tests/progress/test_passives.gd`, `tests/game/test_battle_launcher.gd`

**Interfaces:**
- `Passives.try_unlock(db, c, track) -> String`: returns the unlocked id, or "".
  - It unlocks only when all hold: `affinity_passive` is empty; the track's points reach the threshold; the species lists that track.
  - On success it logs `Log.info(PROGRESS, "Passive unlocked", …)`.
- `Passives.carry_over(db, c, from_species) -> void`, per spec §2.3:
  - the rolled passive keeps its position (or takes the new species' first);
  - the Affinity passive becomes the new species' passive for the same track, or is kept.
- `Progression.award_affinity` keeps its return value. The battle engine emits `PASSIVE_UNLOCKED {bid, passive}` when `try_unlock` returns an id. `BattleRewards.award` calls it and emits the event.
- `ProgressEntry.unlocked_passive: String`. `progress_entry` returns an entry, not null, when the creature levelled or `affinity_passive` changed since `passive_before` (Review Focus 5).

### Task 5: Triggers

**Files:**
- Modify:
  - `core/battle/passive_rules.gd`: `fire(b, on, attacker := null)` and the depth guard.
  - `core/battle/battle_engine.gd`: hooks in `start()` (entry triggers after placement, by speed), `place()` when not at start, `deal_damage()` (`hit`; `absorb_type` before damage), `check_faints()` (`knockout` for the attacker, `faint` for the fainted), `_end_of_round()` (`round_end`, before field ticks), and `"attacker"` handling in `_effect_targets`.
  - `core/battle/effects/effect_context.gd`: `attacker: Battler`.
  - `core/battle/battle_events.gd`: `PASSIVE_TRIGGERED`, `PASSIVE_UNLOCKED`.
  - `game/battle/battle_text.gd`: their lines.
  - `core/battle/effects/op_absorb_type.gd`, a handler registered in `EffectOps`.
- Test: `tests/battle/test_passives_battle.gd`, `tests/game/test_battle_text.gd`

**Interfaces:**
- `PassiveRules.fire(b: Battler, on: String, attacker: Battler = null) -> void`:
  - runs each matching trigger of `b`'s active passive (chance rolled on `engine.rng`; `contact` means the move's category is physical) through `engine.run_effects` with an `EffectContext` (user `b`, source `"passive"`, attacker, default targets per spec §3.2);
  - emits `PASSIVE_TRIGGERED {bid, passive}` first;
  - does nothing while `_depth > 0`, when the battle is over, or when `b` is not alive (except `faint`).
- `PassiveRules.absorbs(target, type) -> float`: the heal fraction, or 0.
- `BattleText` copy:
  - `"%s's %s!"` (name, passive name) for `PASSIVE_TRIGGERED`;
  - `"%s awakened %s!"` for `PASSIVE_UNLOCKED`.
