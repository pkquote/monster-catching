# Roadmap M5–M8 — Design

Date: 2026-11-05
Status: Draft (awaiting review)
Amended 2026-11-11: **M7 Collection and achievements** was inserted after M6
([design](2026-11-11-m7-collection-achievements-design.md)). Art and audio is now M8 and content expansion M9.
Parent spec: [Monster-Catching RPG design](2026-11-03-monster-rpg-design.md) §7 (milestones). Builds on the
[M4 progression design](2026-11-04-m4-progression-design.md) (party, summary and storage screens), the
[held items](2026-11-05-held-items-design.md) and [passives](2026-11-04-passives-design.md) designs, and the
[battle engine reference](../battle-engine.md).

## 1. Goal

Define the milestones after held items, using the playtest notes from 2026-11-05 as the first milestone, so each
later piece of work has a clear place, an order and a reason for that order. This document is a roadmap: it fixes
scope, order and dependencies. Each sub-project listed here still goes through its own brainstorm, spec, plan and
execution before any code is written.

**Success:** the main spec's milestone table gains M5–M8 rows that link here; every playtest note has a named
sub-project; every sub-project says what it depends on; the first sub-project can start without further
roadmap decisions.

### Decisions

| Topic | Decision |
|---|---|
| Order | UI (M5), then engine backlog (M6), then collection and achievements (M7), then art and audio pipeline (M8), then content expansion (M9). Content comes last because it uses everything built before it: the visual screens, new ops, achievements and art slots |
| Granularity | A milestone is a group of sub-projects; each sub-project gets its own spec and plan |
| Placeholders | All art stays placeholder until M8; M5 builds the slots (a creature sprite slot, an item icon slot) that M8 fills; M7 adds an achievement icon slot |
| Test pack | Stays until M9 retires it; the pack is not a milestone deliverable |

## 2. Milestones

### M5 Visual menus

Make the menus visual and easy to parse instead of text menus. Screen size is 640x360; all screens stay fully
keyboard- and gamepad-navigable.

| Sub-project | Scope | Depends on |
|---|---|---|
| **5a Housekeeping** (implemented) | (1) **Controls tab scrolling:** with the arrow keys, the Controls tab in Settings does not scroll to bindings below the visible area; focus must reach every binding and the view must follow it. (2) **Compendium re-audit:** check `tools/generate_compendium.gd` and its output against the current systems (held items, passives, growth tiers, two-foe moves and spread table, party size, the test pack stays excluded), and fix the section order, cross-links and anything missing or misleading. (3) **Bag item summary:** the bag shows a summary of the focused item (name, category, description, price, effect) in a pane on the left, with a placeholder icon slot for art later | none |
| **5b Shared visual pieces** | Reusable UI components: a **creature sprite slot** (placeholder circle in the creature's type colours now, art later; reuses the battle's `creature_view` look), a **stat radar chart** with the numbers shown at each axis, **HP and Stamina bars** drawn under the radar with their numbers, a **creature summary card** that assembles sprite, name, level, types, radar and bars, moves, passives and held item, and an **item icon slot** | none (5a's bag pane uses the icon slot, built here or in 5a, whichever comes first) |
| **5c Summary redesign** | Replace the three-tab Stats / Moves / Training Summary with an easier-to-parse layout built from 5b's card, keeping every current action (switch passive, give/take held item, move set, training, Grow, Reset Seed) | 5b |
| **5d Box and Party** (done) | **Box:** an actual set of boxes, each a grid of slots showing a small placeholder sprite of the deposited creature; moving the cursor over a creature shows its summary card (stats, moves, passives, held item); paging between boxes; deposit, withdraw and swap keep their current rules (including unsafe zones). **Party:** the party view uses the same sprite slots and card in place of text rows | 5b, 5c |

Open questions for the sub-project brainstorms (not decided here):
- 5b: radar axes. Proposal: seven axes (Physical Attack, Physical Defense, Special Attack, Special Defense, Speed,
  Resolve, Luck), with HP and Stamina as the two bars below, because they are resources more than shape. Show
  base-plus-training totals, as the Stats tab does today, and keep the growth ▲/▼ markers.
- 5d: boxes per save, slots per box, how the player switches boxes, whether boxes can be named, and where the party
  sits on the same screen.
- 5c: where training and the Grow prompt live once the tabs are gone.

### M6 Engine backlog

Engine and rules features and cleanups that are queued, none of which depends on M5.

- **Multi-hit moves** (one foe, several hits); the follow-on to the two-target moves.
- **A status-cure op**, so a "full cure" item can exist (the test pack's `tp_full_restore` stands in today).
- **Growth-tier content pass:** mark the shipped species with growth tiers (all 8 are steady today).
- **AI modelling of enter, round-end, faint and knockout triggers** for passives and held items (documented as
  deliberately not modelled today).
- **Remaining minors** from the passives and held-items handoffs that the user chooses to take on, and the two
  pinned engine behaviours to decide: a `one_ally` move can pick its user and falls back to the user when its
  chosen ally has fainted (documented behaviour is a random valid target), and an Underdog creature that swaps
  loses its remaining actions.

Each item is its own small brainstorm; the order inside M6 is chosen when M6 starts.

### M7 Collection and achievements

Track which species the player has seen and caught, show it in a Codex with a detail page (sprite, description,
where to find it), and add an achievements framework that is cheap to extend (data entries, pluggable criteria
kinds, placeholder icons, a pure unlock signal for a later toast or Steam bridge). Full design:
[M7 Collection and achievements](2026-11-11-m7-collection-achievements-design.md).

| Sub-project | Scope | Depends on |
|---|---|---|
| **7a Tracking** | `save.codex` seen/caught per species and `save.counters` lifetime stats, hooks at every way a creature appears or joins, save schema 7 with a backfill | none |
| **7b Codex screens** | Codex list and species detail page (sprite, description, locations); `data/locations.json` generated by `tools/build_maps.gd` | 7a, 5b |
| **7c Achievements** | `achievements` data category, criteria kinds (counter, codex, flag, creature), pure evaluate and a service with `unlocked(id)`, icon slot, Achievements screen | 7a, 5b |

### M8 Art and audio pipeline

Make placeholders replaceable without code changes.

- **Art conventions:** folders and naming for creature sprites, item icons, type badges and UI frames; image
  sizes for the sprite and icon slots from 5b; pixel-art import settings; how a missing image falls back to the
  placeholder.
- **Wiring:** creature, item and type data refer to art by id convention (no new schema fields unless the design
  needs them); the battle scene, Summary, Box, Party and Bag all draw through the same slots.
- **Audio hooks:** music and sound-effect playback on the existing audio buses; hooks for menu, battle, overworld
  and capture events; a mixing and settings check against the Audio tab.
- **Credits and licensing notes** for third-party assets.

### M9 Content expansion

Replace the placeholder content with the real game: the real creature set (with art from M7), moves, maps,
story and tamers; growth tiers on every species; encounter tables per route. The test content pack is retired
as its role is taken over, following the removal checklist in `documentation/battle-engine.md`. This milestone is
split into sub-projects (for example by region or story chapter) when it starts.

## 3. Dependencies

```
5a ─────────────────────────┐
5b ──► 5c ──► 5d            ├──► M8 (slots exist) ──► M9
M6 (independent of M5) ─────┤
M7 (needs 5b) ──────────────┘
```

M5a, M5b and M6 items can run in any order and in parallel with each other. M7 needs the slots from 5b and
adds its own (the achievement icon). M8 needs the slots from 5b and M7. M9 needs M6 (the ops it will use), M7
(achievements to author) and M8 (the art slots filled).

## 4. Process

Each sub-project follows the project workflow: brainstorm (clarifying questions), written spec in
`documentation/specs/`, written plan in `documentation/plans/`, then execution with reviews, and ends with
`bash scripts/check.sh` passing and a suggested commit message. Real-window tours (`--mode=...`) cover new
screens. Headless tests cover logic; screen-fit tests guard the 640x360 layout.

## 5. Out of scope

Online or multiplayer features, localization, mod loading, a map editor beyond the existing editor-built maps,
and detailed designs for the sub-projects (each has its own spec).
