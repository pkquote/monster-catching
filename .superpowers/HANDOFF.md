## Project
Godot 4.7.2 (.NET build, but GDScript only) monster-catching RPG.
- **`core/`** is pure logic: RefCounted classes with no nodes or autoloads. It holds the data defs, battle engine, progression and saves.
- **`game/`** holds the scenes and UI: autoloads, battle scene, overworld, progression screens, debug menu.
- **`data/`** holds JSON content per category. Every category is checked by `core/data/schemas.gd` and `core/data/validator.gd`.
- **`tests/`** uses GdUnit-style suites. Shared helpers are `tests/helpers/fixture_db.gd`, `world_test.gd` and `screen_fit.gd`.
- **Docs:**
  - `documentation/battle-engine.md`;
  - `documentation/compendium.md` (generated by `tools/generate_compendium.gd`, a thin runner over `tools/compendium_builder.gd`);
  - the main design spec `documentation/specs/2026-11-03-monster-rpg-design.md`.

## How to run and test
- Godot console: `/c/Program Files (x86)/Godot_v4.7.2-stable_mono_win64/Godot_v4.7.2-stable_mono_win64_console.exe`
- Full check: `bash scripts/check.sh`. It covers data validation, dialogue check, map check, all test suites and compendium generation, and must end with "All checks passed." It passes with the M5a work in the tree (final run after the review fix wave).
- The `.claude/skills/run-godot-monster-catching-game/` skill launches and drives the real game.
  - Tours: `--mode=frontend|battle|overworld|progress|passives|held|builder|party|bag`, each in `tours/*.gd`.
  - In tour files, `d` is untyped, so values derived from it use `=`, not `:=`.
- Godot test runs share save files, so don't run two test or Godot processes at once.

## Decisions and known small issues
`.superpowers/2026-11-04-passives-handoff.md` lists the 23 rulings made on the user's behalf and the 31 deferred minor issues still open, each with what it costs if wrong. The most notable:
- **Rulings:**
  - Passive-run effects earn no Affinity.
  - A passive trigger that would do nothing (a heal at full HP, energy restore at full energy) is skipped silently.
  - Faint and knockout triggers don't fire on the knockout that ends the battle.
  - An aura's `when` condition is checked on the aura's holder.
  - `underdog` counts only standing creatures on the field.
- **Resolved after the passives commit (all but the AI are in `d18eb44`):**
  - Guardian Aura's text now says "from moves".
  - Foes unlock Affinity passives silently (no "Wild X awakened Y!").
  - Passive banners over the same creature stack instead of overprinting.
  - An absorbed move's other per-target effects skip the absorber (`EffectContext.absorbed`; `deal_damage` returns true when it absorbs).
  - The battle AI is passive-aware (`core/battle/ai/battle_ai.gd`, tests in `tests/battle/test_ai_passives.gd`, documented under "Passives and the AI" in `documentation/battle-engine.md`): absorb, status/stage/shelter blocks, `field_boost`, `rest_bonus`, and hit-trigger retaliation (tactician only). Faint, knockout, enter and round-end triggers are deliberately not modelled.

## Held items (implemented, committed)
- **Spec:** `documentation/specs/2026-11-05-held-items-design.md` (Implemented); **plan:** `documentation/plans/2026-11-05-held-items.md`.
- **What it does:** a creature holds one item (`CreatureInstance.held_item`, save schema 5; tamer party members can set `held_item`). An item with category `held` has a `held` block shaped like a passive (`effects`, `triggers` with an optional `when`, `field`, `scope: allies` for auras) and a usage kind `use`: `permanent` (default), `consumed` (gone after it fires; `ITEM_CONSUMED`, "<Name>'s <Item> was used up.") or `per_battle` (fires once per battle). Banners name the item.
- **Key code:** `core/progress/held_items.gd` (`HeldItems.give/take/def_of`), `PassiveRules` (`held_def`, `fire`, `_use_up`, held effects and auras), `Passives.field_mult` (lead's held `field` ops), `ItemDef.held/held_use`, tactician AI retaliation reads held `hit` triggers, Summary Stats tab Give held item / Swap / Take back (`game/progress/summary_screen.gd`), bag note "Give it from the Summary."
- **Content:** `data/items/held.json`: Tide Charm (permanent type_power), Oran Berry (consumed, heals below half HP), Rough Bark (per_battle, lowers the attacker's Physical Attack), Scout Lens (permanent, encounter_rate field op), Guard Banner (aura). All five are stocked at the Town 1 shop (`tools/build_maps.gd` and `game/maps/town_01_center.tscn`). The compendium has a "Held items" section.
- **Tour:** `--mode=held` (Give held item, a battle where the berry fires, the item gone afterwards). The tour puts the berry in the bag directly: there is no F1 give-item page.
- **Not done / out of scope:** two held slots, steal/knock-off moves, giving items in battle, trading, durability, held items on wild creatures; no held items on tamer parties in shipped data; the AI does not model enter/round-end/faint/knockout held triggers (same as passives); no F1 page to give held items; the shop menu lists all 11 items in two name-only columns, with the price and description shown on the page for the focused item (no categories).
