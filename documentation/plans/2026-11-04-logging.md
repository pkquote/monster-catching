# Logging Implementation Plan

> Executed natively (superpowers:executing-plans), test-first, one fresh reviewer at the end.

**Goal:** A `Log` class with levels per category, console/file/memory sinks, an engine-error bridge, an F1 viewer, applied across battles, saves, overworld/story and progression.
**Spec:** [documentation/specs/2026-11-04-logging-design.md](../specs/2026-11-04-logging-design.md)

## Global Constraints

- `core/log/log.gd` uses no nodes or autoloads. Sinks, config and the viewer live in `game/log/` and `game/debug/`.
- Log calls never change game behaviour, and a failing sink never throws into game code.
- Headless runs default to WARN, so test output stays pristine.
- No commits: the user authors them.

## Tasks

1. **Log core** (`core/log/log.gd`, `tests/log/test_log.gd`).
   - Tests: `test_levels_filter`, `test_category_level_overrides_default`, `test_enabled`, `test_format`, `test_sinks_receive_records`, `test_warn_error_without_sinks_reach_godot` (a no-sink call doesn't crash), `test_reset`.
2. **Sinks, config and autoload** (`game/log/log_file_sink.gd`, `log_memory_sink.gd`, `log_config.gd`, `engine_logger.gd`, `game/autoload/logging.gd`, `project.godot`).
   - Tests: `test_file_sink_writes_and_rotates_to_10`, `test_memory_ring_keeps_last_n`, `test_config_round_trip`, `test_headless_default_is_warn`, `test_engine_bridge_records_push_error_once`.
3. **Replace existing push_error/push_warning calls** in `game/` and `core/` with `Log.error`/`Log.warn`, with categories.
4. **Instrument** battles, saves, world/story, and progress/ui per spec §5.
   - Spot tests: `test_battle_logs_start_round_outcome`, `test_save_write_and_load_logged`, `test_map_change_logged`, `test_level_up_and_growth_logged`, `test_storage_refusal_logged`.
5. **F1 Logs viewer** (`game/debug/debug_menu.gd`).
   - Tests: `test_logs_page_lists_recent`, `test_logs_page_filters_level_and_category`, `test_logs_page_changes_and_saves_levels`.
6. **Docs and verification:**
   - Docs: README, SKILL.md (where logs are, how to raise levels), and a `documentation/logging.md` guide.
   - Checks: `check.sh`, all four tours, then one fresh whole-change review.
